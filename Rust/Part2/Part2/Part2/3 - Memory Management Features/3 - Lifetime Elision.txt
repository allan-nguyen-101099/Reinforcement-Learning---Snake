// Lifetime elision rules — compiler infers lifetimes automatically when:
// Rule 1: Each reference parameter gets its own unique lifetime parameter.
// Rule 2: If there is EXACTLY ONE input lifetime, it is assigned to all outputs.
// Rule 3: If one input is &self or &mut self (method), self's lifetime goes to all outputs.

//Example 1: Single reference parameter — Rule 1 + Rule 2 apply, no annotation needed
fn main() {
    let str_1 = "some str";  // &'static str literal

    let recieved_str = return_str(&str_1);  // borrow str_1
}
// Code with Lifetime Elision (what you write — compiler fills in lifetimes automatically):
// fn return_str(s_1: &str) -> &str {
//     s_1
// }

// Code without Lifetime Elision (what the compiler sees internally):
// 'a is the lifetime — output reference lives as long as input reference
fn return_str<'a>(s_1: &'a str) -> &'a str {  // 'a ties input and output lifetimes together
    s_1  // returning s_1 — output lives as long as s_1 lives
}

// Compiler cannot decide whether the output lifetime matches 'a or 'b — explicit annotation required

/* 
--------------------------------------------------------------------------------------------------------------
Concept / Topic         | Explanation
------------------------|-------------------------------------------------------------------------------------
Lifetime Elision        | Lifetime elision allows the compiler to infer lifetimes automatically.
                        | This reduces the need for explicit lifetime annotations.
                        | If ambiguity remains after applying rules, explicit lifetimes are required.

Elision Rules           | Rule 1: Each reference parameter receives its own lifetime parameter.
                        | Rule 2: If exactly one input lifetime parameter exists, it is assigned to all outputs.
                        | Rule 3: If multiple input lifetimes exist but one is &self or &mut self, then
                        | the lifetime of self is assigned to all output lifetimes.(applies to methods)

Single Parameter Case   | In this case, Rule 1 applies. 
                        | No explicit annotation is needed.

Multiple Parameter Case | In this case, Rule 2 does not apply. 
                        | The compiler cannot infer the return lifetime and reports an error.
                        | Explicit annotations are required.
--------------------------------------------------------------------------------------------------------------
